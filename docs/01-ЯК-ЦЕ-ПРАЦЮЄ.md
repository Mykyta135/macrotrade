# MacroTrade — як це працює

Документ для повернення в проєкт після перерви. Пояснює **структуру системи** і **як її запустити**.

Торгову логіку (що означають сигнали) див. у [02-ТОРГОВА-ЛОГІКА.md](02-ТОРГОВА-ЛОГІКА.md).
Проблеми з даними — у [03-ПЕРЕВІРКА-ДАНИХ.md](03-ПЕРЕВІРКА-ДАНИХ.md). **Прочитайте його перед тим, як довіряти цифрам на екрані.**

---

## 1. Що це взагалі таке

Дашборд для swing-трейдингу (утримання позиції 3–10 днів) на форексі. Система:

1. Тягне макроекономічні дані з безкоштовних джерел (Yahoo Finance, FRED, CFTC, Forex Factory);
2. Проганяє 8 валютних пар через каскад фільтрів;
3. Видає вердикт по кожній парі: **BUY / SELL / WATCH / NO TRADE**;
4. Показує, **чому** саме такий вердикт — які фільтри пройдені, які ні.

Система **не відкриває угоди** і не підключена до брокера. Вона лише каже «дивись на цю пару» — а вхід ви шукаєте вручну на графіку (D1/H4, зони Supply & Demand).

## 2. Чотири окремі сервіси

Це **не** монорепозиторій. Кожна тека — самостійний проєкт зі своїм `package.json`. Встановлювати залежності й запускати треба окремо.

| Тека | Технологія | Порт | Що робить |
|---|---|---|---|
| `backend/` | NestJS 11 + TypeORM + Postgres | **3901** | Тягне дані, рахує скоринг, віддає API |
| `frontend/` | Next.js 16 + Tailwind 4 | **3900** | Дашборд, який ви бачите в браузері |
| `ai-reporter/` | Express + Anthropic SDK | **3902** | Окремо шле дані в Claude, отримує текстовий звіт |
| `forexfactory-scraper/` | Python | — | Разово збирає економічний календар у CSV |
| `data/` | Node-скрипти | — | Офлайн-навчання KNN-моделі |

**Порти 39xx** обрані спеціально, щоб не конфліктувати з іншими локальними проєктами (3000 зазвичай зайнятий).

## 3. Як запустити

### Спочатку — база даних

Postgres вже працює як служба Homebrew на порту **5432**, і в ньому лежать ваші дані (8 таблиць).

> **Не запускайте `docker compose up`.** У `docker-compose.yml` є Postgres, але він **ніколи не стартував** і порожній. Якщо його підняти, ви отримаєте другу, пусту базу. Файл залишений лише про запас; порт у ньому змінено на 5439, щоб випадковий запуск не перекрив справжню базу.

Перевірити, що база жива:

```bash
psql -h localhost -p 5432 -U admin -d macrotrade -c '\dt'
```

Має показати 8 таблиць: `ohlcv_candles`, `technical_snapshots`, `reporter_reports`, `ml_regime_labels`, `trade_journal`, `calendar_events`, `backtest_cache`, `aaii_sentiment`.

### Потім — три сервіси, у цьому порядку

```bash
# 1. Backend — ПЕРШИМ (решта залежить від нього)
cd backend && npm run start:dev        # :3901

# 2. AI reporter — одразу при старті стукає в backend
cd ai-reporter && npm run dev          # :3902

# 3. Frontend
cd frontend && npm run dev             # :3900
```

Порядок має значення: в ai-reporter увімкнено `WARMUP_ON_START`, тому він одразу після запуску йде за даними на `:3901`. Якщо backend ще не піднявся — перший звіт впаде з помилкою.

Дашборд: **http://localhost:3900**

### Якщо порт зайнятий

`EADDRINUSE` означає, що екземпляр уже працює. Знайти й зупинити:

```bash
lsof -nP -iTCP:3900 -sTCP:LISTEN     # подивитись PID
kill <PID>
```

## 4. Куди тече інформація

```
Зовнішні джерела                Backend (:3901)              Frontend (:3900)
─────────────────               ───────────────              ────────────────
Yahoo Finance ──┐
FRED API ───────┤
CFTC (COT) ─────┼──► сервіси ──► ScoreService ──► /api/score ──► CascadeTable
Forex Factory ──┤    (кеш)       (каскад R4→      /api/macro       (таблиця з
alternative.me ─┘                 R1→R2→R3)       /api/... тощо     вердиктами)
                                       │
                                  Postgres
                              (історія, журнал)
```

`ScoreService` — серце системи. Він паралельно питає п'ять сервісів (`macro`, `sentiment`, `cot`, `calendar`, `fred`) і на їхній основі рахує вердикт по кожній парі.

### Кеш — важливо розуміти

Дані **не** тягнуться заново при кожному оновленні сторінки. Кожен сервіс кешує відповідь у пам'яті:

| Джерело | Час життя кешу |
|---|---|
| Macro (Yahoo) | 15 хвилин |
| Sentiment | 15 хвилин |
| Technical | 15 хвилин |
| FRED | 4 години |
| Календар | 1 година (+ 7 днів як запасний варіант) |
| COT | до наступної публікації CFTC (щоп'ятниці) |

Тобто якщо ви бачите дивну цифру — вона могла бути отримана до 15 хвилин тому. **Кеш у пам'яті, тому перезапуск backend його очищає.**

## 5. Ендпоінти API

Усі з префіксом `/api` (наприклад `http://localhost:3901/api/score`).

| Ендпоінт | Що віддає |
|---|---|
| `/score` | **Головний.** Вердикти по всіх 8 парах з поясненнями |
| `/macro` | Індекси, сировина, ETF валют, ADR |
| `/fred` | CPI, безробіття, ставка ФРС, дохідності, крива |
| `/cot` | Позиції хедж-фондів (CFTC) |
| `/sentiment` | Настрої роздрібних трейдерів |
| `/calendar` | Економічний календар, небезпечні зони |
| `/technical` , `/technical/:pair` | Структура ринку, зони S&D |
| `/ml` , `/ml/:pair` | Режим ринку (KNN або fallback) |
| `/ml/regime/all` , `/ml/regime/:pair` | Повна матриця режимів |
| `/backtest?date=YYYY-MM-DD` | Реконструкція стану на минулу дату |
| `/journal` (GET/POST/PATCH/DELETE) | Журнал угод |

Перевірити швидко:

```bash
curl -s http://localhost:3901/api/score | head -c 300
```

## 6. Структура дашборда (після редизайну)

Екран поділено за пріоритетом:

1. **CascadeTable** — головне. Усі 8 пар у таблиці, колонки повторюють порядок обчислення: `R4 → R1 → R2 → R3 → вердикт → блокер`. Клік по рядку розкриває деталі.
2. **ContextStrip** — другорядне. Макро/FRED/COT/Sentiment/Календар стиснуті в один рядок; повні панелі — за кнопкою «detail».
3. **PairSelector / RegimeGate** — глибокий аналіз однієї пари.

Ключові файли фронтенду:

| Файл | Роль |
|---|---|
| `app/components/CascadeTable.tsx` | Таблиця вердиктів (пріоритет) |
| `app/components/ContextStrip.tsx` | Згорнутий контекст |
| `app/components/DashboardClient.tsx` | Компонування + завантаження даних |
| `app/lib/api.ts` | Єдина точка звернення до backend |
| `app/lib/types.ts` | Типи, спільні з backend |

## 8. Змінні оточення

| Файл | Змінні |
|---|---|
| `backend/.env` | `FRED_API_KEY`, `MYFXBOOK_SESSION`, `PORT=3901`, `DB_HOST/PORT/NAME/USER/PASSWORD` |
| `frontend/.env.local` | `NEXT_PUBLIC_API_URL=http://localhost:3901/api` |
| `ai-reporter/.env` | `CLAUDE_KEY`, `PORT=3902`, `BACKEND_URL` |

> **Пастка:** ai-reporter читає ключ як `CLAUDE_KEY`, хоча в `.env.example` і README написано `ANTHROPIC_API_KEY`. Правильний — `CLAUDE_KEY`; документація в тому проєкті помилкова.

**Якщо міняєте порт — треба правити в чотирьох місцях:** `.env` сервісу, `NEXT_PUBLIC_API_URL`, `BACKEND_URL`, і список CORS у `backend/src/main.ts`. Якщо забути CORS — помилка з'явиться лише в браузері, а `curl` працюватиме.

## 9. Небезпечні місця

- **`synchronize: true`** у TypeORM. Будь-яка зміна entity **одразу змінює схему живої бази**. Міграцій немає. Перейменували поле — стара колонка може зникнути з даними.
- **Файл `links` у корені** містить ваш **пароль від Myfxbook** та API-ключі відкритим текстом. Кореневого `.gitignore` немає. Ключі варто перевипустити.
- **Кеш маскує збої.** Якщо зовнішнє API впало, ви можете ще 15 хвилин (або 7 днів для календаря) бачити старі дані без жодного попередження.
