# data/pipeline — калібрування та експерименти

**KNN-модель видалено 2026-07-20.** Тут пояснено чому, з відтворюваними доказами.

## Що тут зараз

| Файл | Призначення |
|---|---|
| `features.js` | Обчислює ознаки з історичних CSV → `features.json` |
| `label.js` | Ставить мітки LOW/NORMAL/HIGH_VOL за перцентилями ATR% → `labeled.json` |
| `experiment-leakage.js` | **Доказ витоку мітки** у старій моделі |
| `experiment-forecast.js` | **Доказ**, що persistence перемагає ML |
| `experiment-regime-change.js` | **Доказ**, що переходи режиму не прогнозуються |
| `_archive/` | Стара модель і тренер (не використовуються) |

`labeled.json` досі потрібен — з нього калібруються пороги класифікатора.

## Чому прибрали KNN

Стара модель заявляла **94.7% точності**. Три експерименти показали, що це число нічого не варте.

### 1. Витік мітки — `node experiment-leakage.js`

Мітка ставиться за порогом `f_atrPct` (див. `label.js`), і той самий `f_atrPct` подавався в модель як ознака №1 з найбільшою вагою (2.0). Модель бачила на вході відповідь.

```
A. Усі 6 ознак (як було)    94.9%
B. Без f_atrPct             74.7%   ← справжня точність
D. Базова лінія             47.0%
```

**20 п.п. точності були фікцією.**

### 2. Persistence перемагає — `node experiment-forecast.js`

У чесній прогнозній постановці (ознаки дня T → режим дня T+1):

```
Persistence "завтра = сьогодні"   93.2%   ← один рядок коду
KNN-прогноз (5 ознак)             76.6%   ← 4.6 МБ моделі
```

Волатильність кластеризується (Mandelbrot 1963; Engle — Нобелівська премія 2003), тому «нічого не змінилось» майже завжди правильна відповідь. **ML програвав тривіальному правилу на 16.6 п.п.**

### 3. Переходи не прогнозуються — `node experiment-regime-change.js`

Persistence має сліпу зону: він ніколи не передбачає змін. Перевірили, чи може ML заповнити її:

```
Стрибок у HIGH_VOL:  спіймано 0 із 25  (усі 12 конфігурацій)
Зміна режиму:        спіймано 2 із 92  (recall 2.2%)
```

**Денні OHLC-свічки не містять сигналу про майбутні переходи.** Для цього потрібні дані, яких у проєкті немає: внутрішньоденні тіки, імпліцитна волатильність з опціонів, розклад новин наперед.

## Що використовується натомість

`MlService.classifyRegime()` — пороги по ATR%, відкалібровані на перцентилях цих же даних:

| Поріг | Значення | Режим |
|---|---|---|
| p33 | 0.662% | нижче → `ranging` |
| p80 | 1.021% | вище → `volatile` |
| p95 | 1.387% | вище → `crisis` |

Між p33 і p80 режим визначає спрямована ефективність (`trending` / `ranging`).

Це дає ту саму інформацію, що й KNN, але: без витоку, без 4.6 МБ, без пайплайну навчання, і `knnConfidence` більше не бреше (тепер це відстань до межі класу, а не частка голосів сусідів).

## Перекалібрувати пороги

Якщо додасте історичних даних:

```bash
node features.js && node label.js
node -e '
const rows=require("./labeled.json");
const a=rows.map(r=>r.f_atrPct).filter(Number.isFinite).sort((x,y)=>x-y);
const p=q=>a[Math.floor(q/100*a.length)];
for(const q of [33,80,95]) console.log("p"+q+":",(p(q)*100).toFixed(4)+"%");'
```

Отримані значення підставити в константи `ATR_PCT_LOW/HIGH/CRISIS` у `backend/src/ml/ml.service.ts`.

## Головний урок

**Точність без базової лінії — беззмістовне число.** 94.7% звучало чудово, доки не з'ясувалось, що тривіальне правило дає 93.2% задарма, а чесна модель — 76.6%.
